# Tailwind Phase 3 — Final Batch Implementation Plan (pipeline swap: retire sass)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Swap the styles pipeline from sass to lightningcss: rename the (already CSS-shaped) `.scss` tree to `.css`, replace the `@use` manifest with a CSS `@import` manifest bundled by lightningcss, point `svg-to-css.js` at the new tree, delete sass + `_variables.scss` + `_colormap.scss` + `colormap_to_theme.bb.clj` + the stray `helpers.css`, and update docs — meeting issue #10's exit criterion (no `.scss` left, `sass` removed, behavior unchanged).

**Architecture:** All 29 component sheets + 10 of 12 base files are already pure CSS in `.scss` clothing (batches 0–3); the two live-sass base files (`_icons.scss` mixins/loop, `_colormap.scss` map) die in the swap because their last consumers do. lightningcss `--bundle` inlines the `@import` manifest into one `dist/css/style.css`, which `build.sh` renames to `3_style.css` exactly as before — `build.sh`, `gather-assets`, and every bundle `index.html` are untouched. Output equivalence is gated at three levels: normalized rule-set diff (batch-0 parity technique), the computed-style harness, and the full screenshot sweep.

**Tech Stack:** lightningcss-cli 1.32.0 (installed; `--bundle` + `--targets '>= 0.25%'` — the exact invocation proven by the batch-0 parity harness `styles/scripts/nesting-parity.sh`), Tailwind v4.3.2 (untouched), chokidar-cli (already a dep, for watch).
