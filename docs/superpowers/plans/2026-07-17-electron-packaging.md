# Electron Packaging Rebuild (issue #28) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the electron packaging pipeline orphaned by the 3ac8251 backend/frontend split: three prod build configs (main process, worker/backend, UI/frontend), the prepare/bundle Makefile chain, the electron-ABI native-module step, and an actual boot verification — so `make build-linux` produces a working AppImage again and `make dev-app` launches the app.

**Architecture:** Reproduce the deleted lein build's OUTPUT CONTRACT with deps.edn-era tooling. App root = `dist/electron/prepared/` (holds `package.json` + `main.js` + `node_modules/` + `public/`). Main + backend compile with `cljs.main :optimizations :simple :target :nodejs` (requires resolve at runtime from the shipped `node_modules`, exactly like the old build — `better-sqlite3`'s native binding must be an external file anyway). Frontend compiles browser-style `:simple :target :bundle` + webpack → `public/js/frontend.js` (the server bundle's proven pattern). The electron-ABI better-sqlite3 binding comes from the WiseLibs prebuild download (restoring the deleted `prebuild-node-modules.sh` mechanism).

**Tech Stack:** ClojureScript 1.12.134 (`cljs.main`), webpack 5.104.1 (already a backend devDep; frontend has webpack via its own devDeps — verify), electron 28.2.2 (ABI v119), electron-builder (installed globally at bundle time, as before), xvfb-run for headless boot checks.

## Global Constraints (verbatim facts from the deleted `project.clj` — the output contract)

- **Layout** (all under `dist_root=../../dist/electron`, `prepared` = app root):
  - `prepared/package.json` (copied by `gather-assets.sh prod`, which also runs `npm install` in `prepared/` and copies html + preload JS to `prepared/public/` and `assets/{css,fonts,img}` to `prepared/public/`)

  - `prepared/public/js/backend.js` ← `de.explorama.backend.woco.app.core`, `:target :nodejs`, `:simple`
  - `prepared/public/app/` ← copy of `backend/resources/public/app/` (icons/installer art — `gather-assets.sh` does NOT copy it; the Makefile must, as the old one did)
- **Closure-defines (prod)** — from the old `prod-envs`/`set-*-envs`, keyed for cljs.main edn options:
  - all three builds: `goog.DEBUG false`
  - main: `de.explorama.main.config/DEFAULT_LOG_LEVEL "info"`, `de.explorama.main.config/RUNTIME_MODE "prod"`
  - backend + frontend: `de.explorama.shared.woco.config/DEFAULT_LOG_LEVEL "info"`, `de.explorama.shared.woco.config/RUNTIME_MODE "prod"`
  - backend ONLY: `de.explorama.shared.common.configs.provider-impl/CONFIG` = the bucket-config EDN string — copy the exact value from `backend/deps.edn`'s `:test-ci` inline `-co` (single-escaped for an edn FILE, i.e. like `backend/deps.edn` has it but with one escaping level removed — `{:explorama-bucket-config {"default" {:backend "browser" :indexed? true :schema "default" :data-tile-keys {...}}}}` as a string). `:backend "browser"` is ignored by the electron sqlite impls; `:indexed? true` + `:data-tile-keys` are load-bearing. `CURRENT_ENV` needs NO injection (each half's `scope.cljs` bakes the right default).
- **Entry semantics:** `main/core.cljs` ends with `(set! *main-cli-fn* -main)` — under `:target :nodejs` the compiled `main.js` self-runs. `worker.html` loads `js/backend.js` bare (backend core self-inits). `index.html` loads `js/frontend.js` then calls `de.explorama.frontend.woco.app.core.init()` — the frontend build must keep that export callable (`:simple` + webpack, same as the server bundle, preserves it).
- **Native module:** better-sqlite3 stays pinned 9.4.0. The electron runtime needs the electron-ABI binding: download `better-sqlite3-v9.4.0-electron-v119-linux-x64.tar.gz` (win: `win32-x64`) from `https://github.com/WiseLibs/better-sqlite3/releases/download/v9.4.0/…`, untar, copy `build/` over `prepared/node_modules/better-sqlite3/build/` — the mechanism of the deleted `prebuild-node-modules.sh` (get its verbatim body from `git show 3ac8251^:bundles/electron/prebuild-node-modules.sh` and adapt paths; it now lives in `bundles/electron/` again since it's a whole-app concern). NOTE: `prepared/`'s `npm install` on modern Node will FAIL building 9.4.0 from source — run it `--ignore-scripts` and let the prebuild copy supply the binding (document this in the script; `gather-assets.sh prod`'s `npm install` line needs the same flag).
- **electron-builder:** config lives in `backend/package.json` (`"build"` block, icons referenced `../public/app/…` relative to `prepared/` — correct once `app/` is copied). Old chain: `clean_modules.sh` shrink → `npm install -g modclean` etc. → `electron-builder --linux` in `prepared/` → `mv dist/*.AppImage ../` → `rm -rf prepared`. Keep `rm -rf prepared` OUT of the new bundle target until T4's boot check has run (order: prepare → verify → bundle).
- Do NOT touch: test aliases/`:test-ci`, `run-tests-ci.bb.clj`, the CI workflow, `styles/`, anything the earlier PRs settled. `frontend/prod-opts.edn` may be REPLACED (its current content is a broken copy-paste of a server-style config that never matched electron's layout); `backend/prod-opts.edn` likewise (it compiles the WRONG ns today).
