### Grid collision analysis (issue #18 special investigation — RESOLVED)

The `.dashboard__layout` grid system (`_dashboards.scss` L374-404) is a SCSS `@for $i from 1 through 12` loop generating `&.c#{$i}` (`grid-template-columns: repeat($i,1fr)`), `&.r#{$i}` (`grid-template-rows: repeat($i,1fr)`), and on `.dashboard__item`: `&.w#{$i}` (`grid-column-end: span $i`), `&.h#{$i}` (`grid-row-end: span $i`), `&.x#{$i}` (`grid-column-start: $i`), `&.y#{$i}` (`grid-row-start: $i`) — i.e. `c1..c12`, `r1..r12`, `w1..w12`, `h1..h12`, `x1..x12`, `y1..y12`.

**Collision check (against `docs/superpowers/artifacts/tailwind/old-utilities.edn`, 2681 entries, and Tailwind v4 builtins):**
- Tailwind's own grid utilities are `grid-cols-N`, `col-span-N`, `col-start-N`, `col-end-N`, `row-span-N`, `row-start-N`, `grid-rows-N`, and dimensional `w-N`/`h-N` — **all dash-separated**. The markers `c1`/`r1`/`w1`/`h1`/`x1`/`y1` have **no dash**, so there is **no Tailwind builtin of the same name**.
- `old-utilities.edn` grep: **no key** named `c1..c12`, `r1..r12`, `w1..w12`, `h1..h12`, `x1..x12`, or `y1..y12`. The only grid-ish old utilities are `col-1..col-12` (the SEPARATE legacy `col-*` grid, distinct namespace, `_temp`/`_forms_domain`-owned) — NOT the dashboard `c*` markers.

**Verdict: the grid markers are SAFE — neither a Tailwind-builtin collision nor load-bearing old-utility composition.** No `!` / arbitrary-value collision handling is needed.

**But the grid CANNOT migrate to markup, for two independent reasons:** (1) the class names are DYNAMICALLY CONSTRUCTED via `(str "c" gw)` / `(str "r" gh)` / `(str "x" x)`… in `template_schema.cljs` (L12-20) and `template_builder.cljs` (L125-135) — split-token construction that the Tailwind scanner silently drops (would require `@source inline(...)` of all 72 classes); (2) the values are RUNTIME-PARAMETERIZED (`repeat($i,1fr)`, `span $i`, grid-start `$i`) from template data — an arbitrary Tailwind utility with a runtime `N` is not statically scannable either. **Disposition: relocate the `@for` grid loop + the paired `.dashboard__layout.preview` block + the responsive `@media` block VERBATIM into `_dashboards_domain.scss`; leave the `(str …)` construction in the two cljs files UNTOUCHED. The grid STAYS A REMNANT** (Task 3).
